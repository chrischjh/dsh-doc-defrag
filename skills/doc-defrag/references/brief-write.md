# brief-write · 写作简报模板

> 一份权威文档 = 一个 subagent。**质量全在这份简报里**：骨架承载领域知识，模型只负责取事实填进去。

---

你要在仓库 {{REPO}} 里**写一个新文档**：`{{TARGET_FILE}}`（用 write 工具创建）。

## 硬规则

- **只允许写 `{{TARGET_FILE}}` 这一个文件**。不修改、不移动、不删除任何其它文件；不做 git 操作。
- 只写**事实**，全部来自仓库里现有文档（用 read/grep 读）。**禁止凭记忆编造**命令、端口、路径、IP、数字、版本号。
- 无法确认的写 `> TODO 待核：…`，不要含糊其辞、不要猜。
- 引用来源时用**归档后的路径**：`docs/x.md` → `docs/archive/root/x.md`；`docs/architecture/x.md` → `docs/archive/architecture/x.md`；`docs/ops/x.md` → `docs/archive/ops/x.md`；证据目录 → `docs/archive/evidence/<原目录名>/`。正文里写《文件名》，必要时括号给归档路径。
- 中文；标题用 `#` / `##`；写成**照着能复现的手册**，不要写成史书。
- 每个关键步骤后面跟一行 `判据：…`（可执行、可核对）。
- 同一事实两处矛盾 → 写「**现行口径 + 历史口径注**」，不要裁决。
- 不写"本文档描述了…"这种复述；不要贴大段原文。

## 风格要求

- 命令全部放 ```bash 代码块，保留真实变量名；不确定的参数用 `<占位>` 并说明。
- 表格用于清单与矩阵；不要用表格装散文。
- 数字必须带口径（日期/环境/来源）；冲突数字并列表述。
- 全文 {{MIN_LINES}}–{{MAX_LINES}} 行。宁缺毋滥。

## 完成后

回一句 300 字内的摘要：写了多少行、覆盖哪几节、有哪些 `TODO 待核`、有无发现的冲突。

## 使用说明（给派活的 agent）

1. **先出第一份给用户验收风格**，再批量派剩下的——风格错了批量返工代价最大
2. 简报里的 {{SKELETON}} 是这份简报的核心：把该行业的章节约定（见 `archetypes.md` 的槽位）展开成具体小节
3. 写作 subagent 只写一个文件；`docs/README.md` 的路由表由主 agent 最后统一生成，别让它改
4. 回来后立刻 `ledger check` 该组的 target 是否都存在；写作 subagent 说"只写了这一个文件"，就用 `git status` 复核一遍
