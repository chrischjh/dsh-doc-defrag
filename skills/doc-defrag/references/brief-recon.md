# brief-recon · 只读考古简报模板

> 给每个目录组派一个 subagent。**核心槽位是「判定基准」**——没有它，"过时"就只能靠猜。

---

你在 {{REPO}} 对 `{{DIR}}` 做**只读考古**。严格禁止任何写操作：不创建、不修改、不删除、不移动文件，不做 git 写操作；只用 read / glob / grep / ls / wc 等只读命令。

## 范围

`{{DIR}}` 下**全部 {{N}} 个 .md**（完整清单用 `ls`/`glob` 获取，务必**逐个读完**）。
>100KB 的文件可只读标题结构 + 每节开头，但**必须在清单里标注「仅读结构」**。
`.json` / `.csv` 只看名称与首行判主题，不必全读；图片/压缩包不读。

## 判定基准（不许跳过）

- **今天是 {{DATE}}**。
- 项目最近完成了：{{RECENT_MILESTONES}}（例如"同步 v2→v3 升级""权限三期""某迁移收尾"）
- 文件名日期越大越新；文档自述"已被取代/已完成/已废弃"以**内容**为准。
- 这几份是**最新**的：{{NEWEST_FILES}}
- 这几类**已被取代**：{{SUPERSEDED_CLASSES}}（例如"v1.2/v1 系方案""A 代设计"）

## 最终目标

这些素材要归并进 {{M}} 份文档：

{{TARGET_DOCS}}
（每份写成：`序号 名称 —— 管什么；不管什么`）

其余全部进 archive。

## 输出（紧凑中文，≤{{LINES}} 行，信息密度优先）

### A. 清单
| 文件 | 日期/版本 | 主题(≤15字) | 状态 | 归属 |
|---|---|---|---|---|
状态取：`当前有效` / `已被取代` / `过程记录` / `纯证据` / `仅读结构`
归属取：`{{1..M}}` 之一，或 `archive`

### B. 关键事实
按归属分组，每条一行（≤2 行），**必须写具体内容**：表名/字段/接口/脚本名/端口/路径/版本号/数字/命令/结论；行尾用 `《文件名》` 标来源。
禁止"该文档描述了…"这类复述。

### C. 冲突与过时判定
逐条写：哪份被哪份取代；彼此矛盾的结论（端口/路径/口径/步骤/数字）分别是什么、**应以哪份为准**、依据是什么。

### D. 疑点
最多 5 条需要人确认的（写成问句，附候选答案）。

---

**要求**：不要空话。输出要能**直接拿去写新文档**。

---

## 使用说明（给派活的 agent）

1. **按目录组切分**，每组 ≤70 个 .md；超过就再切
2. 每组一个 subagent，**并行派**；回来一组再派下一组（避免一次 6 个全在等你）
3. subagent 失败（error，无收尾消息）→ **换名字重派**（`w-05` → `w-05b`），简报不变
4. 每组的 A 清单直接汇进 `.defrag/ledger.md`；B/C/D 分发给对应的写作 subagent
5. 清单里出现"仅读结构"的文件，在台账 `reason` 里注明，别当成读全了
